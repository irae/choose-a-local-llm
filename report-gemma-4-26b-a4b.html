Gemma-4-26B-A4B (MoE) on M1 Max 32 GB

llama-server (build 10621) · unsloth UD-Q4_K_XL + MTP draft · benchmarked 2026-08-25

Summary

The MoE big sibling of Gemma-12B does everything its family does, faster: 71.9 py / 69.3 js tok/s with thinking on (74.8 / 71.6 with thinking off) at MTP depth 2, the full 256K trained window on one slot (21.6 GB RSS), and two 192K slots (q8_0 KV) for concurrent agents. Thinking (binary, default off) costs only ~3 tok/s. Quality gate (EvalPlus) pending.

Two concurrent agents — 2×192K slots, q8_0 KV (pi id gemma-4-26b-a4b-2x; 2×256K produced Metal errors — not usable):

llama-server -hf unsloth/gemma-4-26b-a4b-it-GGUF:UD-Q4_K_XL \
  --alias gemma-4-26b-a4b-2x --no-mmproj \
  --spec-type draft-mtp --spec-draft-n-max 2 --parallel 2 \
  -ngl 999 -fa on -c 393216 \
  --cache-type-k q8_0 --cache-type-v q8_0 \
  --jinja --port 8081

Speed is nearly flat in context (74.8 at 32K → 67.8 at 256K), so the 256K single-slot config is the sensible default. Thinking: binary enable_thinking (trained-in <|think|>, default off, no effort levels); all speed numbers here were measured with thinking off.
